# RR2 — глибоке рев'ю шляху фото → вердикт (звіт незалежного ревьюера)

Ревьюер — субагент (Opus), який не бачив, як писали код, і не змінював файли. Ліміт — 5 пунктів.
Фокус: чи можуть збій моделі, частково валідна відповідь, порожня екстракція, дедлайн або
кеш дати `pass`; чи можуть ключі потрапити в логи, відповідь чи БД. Мережі й живого LLM не було.
Перевірка — запуском у `docker compose run --rm -T test python -`:
- `validate()` + `run_rules()` на зіпсованих відповідях моделі;
- `_excerpt` з ключем на межі 300 символів;
- повний `POST /checks` через ASGI з БД `label_check_test`, `FakeVision` і `GeminiVision`
  на `httpx.MockTransport` (403).

Що в порядку (перевірено):
- Ключі лише в заголовках (`x-goog-api-key`, `Authorization: Bearer`), не в URL.
- Мережеві винятки httpx потрапляють у повідомлення лише як ім'я типу (`from None`).
- Логер `httpx` — на рівні WARNING, а `raw_text` — лише відповідь моделі.
- Збій моделі або повторна невалідна відповідь → `status=error` без вердикту, у кеш нічого не пишеться.
- `{}` → `needs_review` (`LABEL-MISSING`, `SIDE-FRONT-MISSING` `not_checked`).
- Ключ кешу містить `PROMPT_VERSION` і модель, тож відповідь запасної моделі не підмінює відповідь основної.
- Коментар в `app/logs.py:52` про ключ у query URL Gemini застарів.

## Виправлення

- **№ 1** — `app/rules/general.py` (`check_front`). Якщо фото фронту є, а в `other_text` немає
  жодного читабельного елемента (відсутній ключ, `null`, `[]` або лише `[…]`), то
  `SIDE-FRONT-MISSING` дає `not_checked` з текстом «текст поза складом і таблицею не
  розпізнано — твердження не перевірено». Тоді вердикт ≠ `pass`, і кешований результат
  дає ту саму відповідь, бо правила виконуються знову.
  - `extra="forbid"` свідомо не вводили: зайвий ключ від моделі давав би повтор і
    502 `vision_bad_output`, а перейменований ключ ловить нове правило.
  - Тест `test_lost_other_text_is_never_pass` покриває 5 варіантів; без виправлення
    падають усі 5.
  - Фікстура `label()` тепер кладе на фронт назву продукту. SPEC §2 оновлено.
- **№ 2** — `_excerpt`: спершу маскування, потім `[:300]`. Тест
  `test_key_across_the_excerpt_boundary_is_hidden` (зсуви 285/290/295); без виправлення
  падають усі 3.
- Коментар у `app/logs.py` виправлено.
- **№ 3, № 4** — дрібниці, відкриті в `docs/NOTES.md`.
