# Label Check

Сервіс за фото упаковки (1–4 фото) перевіряє маркування харчового продукту за законодавством
України: алергени (Закон № 2639-VIII) і твердження про поживну цінність (Наказ МОЗ № 1145).
Для R&D-технолога, який зараз годину звіряє кожну упаковку вручну: сервіс робить цю звірку і
віддає людині лише те, що сам не може підтвердити.

## Архітектура: модель читає, код вирішує

```
фото (1–4) → підготовка (тип/розмір, EXIF-поворот, ≤ 2048 px, sha256)
          → vision-LLM (Gemini): ЛИШЕ транскрипція в JSON — склад з **виділенням**,
            числа рядками як на фото, «[…]» на обрізаному, увесь інший текст упаковки
          → кеш екстракції (sha256 фото + PROMPT_VERSION + модель)
          → код: розбір чисел і розмітки, словник алергенів, пошук тверджень
          → правила (чисті функції, кожне з legal_ref) → findings
          → вердикт: fail > needs_review > incomplete > pass
          → PostgreSQL: фото, сира відповідь моделі, екстракція, findings, версії (аудит)
```

Модель ніколи не вирішує, чи є порушення, і не пише тексти повідомлень. Пороги, арифметика,
словник алергенів, регулярки тверджень, повідомлення й посилання на закон — у коді й покриті
тестами (`make test`, 600 тестів, без мережі й ключів). Сумнів → `needs_review`, ніколи `pass`:
пропущене порушення (відкликання партії) гірше за зайву хвилину технолога.

Стек: Python 3.12, FastAPI, PostgreSQL 16 (asyncpg, SQL-міграції), Gemini REST через httpx,
Pillow, Docker Compose, pytest, GitHub Actions.

## Запуск за 3 команди

```bash
cp .env.example .env      # вписати GEMINI_API_KEY (Google AI Studio, free tier, без картки)
make up                   # db + api на 127.0.0.1:8010
make health               # {"status":"ok","db":"ok","vision_provider":"gemini","vision_fallback_provider":null}
```

Swagger UI: http://localhost:8010/docs. Тести (offline, окрема БД `label_check_test`): `make test`.
Порти 8010 і 5433 (лише `127.0.0.1`).

## API

- `POST /checks` — multipart: `images` (1–4 фото), `spec` — необов'язкова рецептура (JSON
  `ProductSpec`: інгредієнти з алергенами, «може містити», поживна цінність на 100 г, форма).
- `GET /checks/{id}` — збережена перевірка (і та, що завершилась помилкою моделі).
- `GET /rules` — перелік правил з посиланнями на закон; `GET /health`.

Приклад (синтетична етикетка «Sugar free» з 24 г цукру, `eval/cases/dev/dev-005`):

```bash
curl -s -X POST localhost:8010/checks \
  -F images=@eval/cases/dev/dev-005/photo_0.jpg -F images=@eval/cases/dev/dev-005/photo_1.jpg
```

Відповідь (реальний запуск, скорочено: показано finding з порушенням і 1 з 4 `not_checked`):

```json
{
  "check_id": 6, "status": "done", "verdict": "fail",
  "summary": "Є порушення — етикетку потрібно виправити. (порушення: 1, не перевірено: 4, пройдено: 10)",
  "findings": [
    {"rule_id": "sugar_free", "target": "sugar_free", "status": "violation",
     "message": "Твердження «без цукру»: цукри 24 г на 100 г, поріг ≤ 0,5 г — поріг перевищено.",
     "evidence": {"photo_index": 0, "fragment": "Sugar free", "values": {"sugars": 24.0}, "threshold": 0.5},
     "legal_ref": "Наказ МОЗ № 1145 від 15.05.2020, перелік тверджень про поживну цінність; Регл. (ЄС) 1924/2006, додаток"},
    {"rule_id": "ALG-SPEC-MISSING", "target": null, "status": "not_checked",
     "message": "Без рецептури не перевірити, чи всі алергени зазначено на етикетці.",
     "legal_ref": "Закон України № 2639-VIII «Про інформацію для споживачів щодо харчових продуктів» ст. 6 ч. 1 п. 3, ст. 15 ч. 1, дод. 1; Регл. (ЄС) 1169/2011 ст. 9(1)(c), ст. 21(1), дод. II"}
  ],
  "model": "gemini/gemini-3.5-flash-lite", "rules_version": "2026-10-02.1",
  "prompt_version": "2026-10-01.1", "cache_hit": true, "duration_ms": 2

```

Помилки — `{"error": {"code", "message"}}`: фото `image_too_large`, `image_unsupported`,
`too_many_images` (422); vision `vision_not_configured`, `vision_invalid_key`,
`vision_rate_limited`, `vision_unavailable`, `vision_timeout` (504), `vision_bad_output`,
`vision_error`. Помилка моделі зберігається в БД зі `status=error` і ніколи не дає вердикту.

## Число довіри

**safe recall 97 % (30/31, 95 % інтервал 84–99 %) при навантаженні 26 % чистих етикеток
(базова лінія 100 %).** Тобто з 31 відомого порушення в test сервіс показав технологу 30
(як `violation` або `needs_review` саме за цим правилом і об'єктом), а з 19 етикеток без
порушень віддав людині 5. Базова лінія «все → needs_review» теж має recall 100 %, але
навантаження 100 %: цінність сервісу — у різниці 100 % → 26 %.

- **Звідки 30/31:** синтетика **15/16** + напівсинтетика на справжніх українських фото
  **15/15**. Напівсинтетика перевіряє **лише `ALG-SPEC-MISSING`**: до справжнього фото
  дається рецептура з алергеном, якого на етикетці немає.
- **Strict recall** (лише `violation`) — **81 %** (25/31): частина порушень за задумом іде в
  `needs_review` (напр. невиділений алерген — ніколи не `violation`, бо модель губить жирний).
- **Справжні UA-фото** (10 упаковок з Open Food Facts) **власних порушень не мають**: вони
  міряють хибні тривоги, навантаження і точність читання, а не recall. Усі 5 навантажених
  чистих етикеток — справжні, зі спірним (`meta.ambiguous`, напр. «ароматизатор гірчиці»).
- **Мала вибірка → широкий інтервал:** 31 порушення дає 84–99 %; «97 %» не означає «пропускає
  3 з 100».
- Хибні `violation` на чистих: 1 з 19 (r13, «без доданого цукру» — у розмітці спірне).
- Точність читання (40 кейсів): числа таблиці 334/340 = 98 %; «не виділено» — precision 9/9,
  recall 9/10; знайдені твердження 20/20.
- Проблеми фото (окрема метрика, не в recall): обрізаний склад помічено 2/3, погане фото 2/4,
  відсутній склад/таблиця 3/3.
- **Поза ринком, для інформації** (5 неукраїнських етикеток, у головне число не входять):
  safe recall 8/9, навантаження 2/4.
- Єдиний пропуск — test-003: алерген «полба» відсутній у словнику (втрата в правилах, не в
  читанні: правила на ідеальній екстракції теж його не бачать).

Звіт: [`eval/reports/test_2026-10-01.md`](eval/reports/test_2026-10-01.md) (+ `.json` з
кожною перевіркою). Модель `gemini-3.5-flash-lite`, 45 екстракцій, ≈ 195 тис. токенів.

### Як отримано

- **Набір test** (55 перевірок у головному числі): 30 синтетичних етикеток
  (`eval/generate.py`, Pillow, фіксований seed, **позначені як синтетичні**) з відомими
  порушеннями з каталогу (невиділений алерген, «без цукру» при цукрах > 0,5 г, «джерело
  білка» < 12 % енергії, «низький вміст жиру» понад поріг, «без доданого цукру» з медом/
  сиропом, енергія не сходиться, алерген рецептури відсутній на етикетці) і чистими (зокрема
  «без цукру» при «<0,5 г»); якість — чисте, розмите, повернуте 2–5°, JPEG 40 %, обрізане;
  + 10 справжніх українських упаковок з OFF (розмічав субагент; основний контекст фото не
  бачив) + 15 напівсинтетичних рецептур до них.
- **Чесність:** dev і test розділено; формулювання інгредієнтів — з **окремих пулів**
  (`eval/pools/dev.yaml` / `test.yaml` не перетинаються, є форми поза словником — `meta.oov`
  — і пастки на кшталт «кокосове молоко»); промпт, словник і пороги налаштовувалися лише на
  dev; test заміряно **один раз**, після нього нічого не змінювали. Продуктові лінії з
  dev-фото з test прибрано (витік); неукраїнські етикетки — окремою групою.
- **Зарахування** лише за парою `{rule_id, target}`, не за вердиктом: `needs_review` через
  розмите фото не «знаходить» порушення «без цукру». Помилки моделі не в знаменнику, але
  показані окремо (на test їх 0).
- **Правила на правді = 100 %:** тест `tests/test_truth.py` проганяє правила на ідеальній
  екстракції кожного синтетичного кейсу — збіг точний; для oov-кейсів — після додавання
  саме oov-слів. Так видно, де втрати: у читанні чи в правилах.
- **Dev** (30 синтетичних): safe recall 15/16 = 94 % [72–99 %], навантаження 25 % — і до, і
  після B6 (покращення не прийнято, див. нижче).

### Відтворити число без ключа і без фото

Кожна відповідь моделі закомічена в `eval/cache/<split>/<case_id>.json` (екстракція, сира
відповідь, токени, модель, PROMPT_VERSION, sha256 фото). Тому на чистому клоні:

```bash
make eval SPLIT=test      # жодного виклику моделі: усе з eval/cache, правила — на поточному коді
```

дає те саме число (перевірено: справжні фото, яких немає в git, прибрано — звіт ідентичний).
`make eval-live SPLIT=…` викликає модель лише для кейсів без кешу (пауза `EVAL_PAUSE_SECONDS`).
`make generate` відтворює синтетику з seed, `make semisynth` — напівсинтетичні рецептури.

### Чесні межі

Синтетика — рендер на Pillow, легший за справжні фото (обрізання на ній модель ловить 2/2).
Справжніх українських упаковок 10, і власних порушень у них немає. Номери статей Закону
2639-VIII звірено з текстом на zakon.rada.gov.ua (B7); повний текст Наказу МОЗ № 1145 не
відкривався — пороги тверджень узято з додатку Регламенту 1924/2006, який наказ відтворює.

## Як працює перевірка — на прикладі одного finding

Фото dev-005 → модель повертає транскрипцію: `other_text` містить `{"text": "Sugar free",
"photo_index": 0}`, `nutrition.sugars = "24 г"`, `per = "100g"`. Далі тільки код:

1. `find_claims` знаходить у тексті регулярку `sugar_free` (`(?:sugar|zero sugars?) free`
   після нормалізації дефісів) — твердження шукає код, не модель.
2. `parse_amount("24 г")` → `{value: 24.0, qualifier: "eq"}` (кома — десятковий роздільник;
   `"<0,5 г"` дало б `qualifier: "lt"`, і «без цукру» пройшло б).
3. Поріг `sugar_free` ≤ 0,5 г на 100 г (Наказ МОЗ № 1145 / Регл. 1924/2006) → 24 > 0,5 →
   `violation`; число в `message` і `evidence.values` порахував код.
4. Будь-яке `violation` → вердикт `fail`. Без рецептури перевірки алергенів проти рецептури —
   `not_checked`, тому навіть чиста етикетка без рецептури отримала б `incomplete`, а не `pass`.

## Що спробували і не прийняли

**B6: другий, вузький виклик моделі на виділення алергенів.** На dev 6 з 8 «не виділено» були
хибні (precision 25 %): модель губить жирний шрифт на стиснутих і повернутих фото — це
головне джерело навантаження. Спроба: для слів-алергенів, які код знайшов без `**`, окремо
питати лише фото складу «так / ні / не впевнений» (pass лише на «так», `violation` — ніколи),
з окремим кешем і версією. Критерій прийняття на dev: safe recall ≥ 15/16 **і** навантаження
< 25 %. Результат: recall 15/16, **навантаження 25 % → 25 %**, precision «не виділено»
25 % → 29 % — модель і на вузьке питання відповідає «ні» про жирні слова. **Відкат**; висновок —
це межа моделі на таких фото, а не формулювання питання.

## Рев'ю

Два глибокі рев'ю незалежним субагентом (звіти в `docs/reviews/`), кожна знахідка доведена
запуском і закрита регресійним тестом:

- **RR1 (ядро правил): 7 сценаріїв, де порушення давало `pass`** — склад обрізався на «ДСТУ»
  посеред списку; «без доданого цукру» з концентратом соку/солодовим екстрактом; твердження
  «без цукру та жиру», «0 г цукру», «low fat» не знаходились; алерген у назві інгредієнта
  рецептури без `allergens`; рецептура «пшениця» проти етикетки «овес»; «глютен» замість назви
  злаку; енергія лише в одній одиниці. Плюс прогалини словника (жовток, пахта, сардина…).
- **RR2 (шлях фото → вердикт): 1 `pass` на порушенні** — якщо модель губила поле `other_text`,
  твердження не шукались і «без цукру» при 3,1 г давало `pass` (ще й кешувалось); тепер це
  `not_checked`. І частина API-ключа могла потрапити в повідомлення про помилку провайдера
  (маскування після обрізання) — виправлено.

## Рішення і компроміси

- **Ринок — Україна**, мова етикетки українська; правова база — Закон № 2639-VIII
  (гармонізований з Регламентом 1169/2011) і Наказ МОЗ № 1145 (= додаток Регл. 1924/2006).
  Кожне правило має `legal_ref` (`GET /rules`).
- **Рецептура — еталон для алергенів**, але необов'язкова: без неї сервіс не стверджує
  повноту алергенів (`not_checked`, вердикт не `pass`).
- **Виділення алергенів без `**` — лише `needs_review`**, ніколи `violation`: проба показала,
  що модель пропускає жирний шрифт (і B6 це підтвердив).
- **Числа — рядками з фото, розбирає код**; обрізане — маркер `[…]` → `LABEL-TRUNCATED`.
- **Лише 13 тверджень про поживну цінність**; порівняльні, про здоров'я, нерегульовані
  («натуральний») → `CLAIM-UNVERIFIABLE` (`needs_review`).
- **Моделі:** основна `gemini-3.5-flash-lite` (free tier: 15 RPM, 250K TPM, 500 RPD;
  `gemini-2.5-flash` має лише 20 RPD). Запасна — Groq `qwen/qwen3.8-27b`
  (`VISION_FALLBACK_PROVIDER=groq`, лише запити з ≤ 3 фото); число довіри міряється тільки на
  основній (eval вимикає запасну). Повтори на 5xx/таймаут 2/4/8 с, 429 — без повторів;
  спроба ≤ `VISION_TIMEOUT_SECONDS` (45), уся екстракція ≤ `VISION_DEADLINE_SECONDS` (120).
- Фронтенду немає — демо через Swagger UI.

## Чим пожертвували

- Одна vision-модель безкоштовного рівня; немає ансамблю чи другого читання.
- Мала справжня вибірка (10 UA-упаковок без власних порушень) — recall на справжніх фото
  лише через напівсинтетику.
- Твердження про користь для здоров'я, порівняльні й «натуральний» не оцінюються автоматично.
- Немає авторизації, черги й UI; один процес api.

## Що далі

- Сильніша модель (або кроп складу зі збільшенням) лише для виділення алергенів — головне
  джерело навантаження (див. B6).
- Більше справжніх українських упаковок з реальними порушеннями; дорозмітити 3 вже
  завантажені продукти (печиво, соус, крекер) і додати бракуючі категорії.
- Словник алергенів: форми, що вийшли поза ним у вимірі (рікота, кус-кус, полба, сулугуні…).
- Повний текст Наказу МОЗ № 1145 — звірити пороги тверджень.
